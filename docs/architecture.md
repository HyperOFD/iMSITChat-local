# Архитектура

На компьютере преподавателя работают три сервиса. Nginx обслуживает файлы SPA и передаёт запросы с префиксом `/api/` в FastAPI. Браузер использует один origin и одну HttpOnly cookie. FastAPI обращается к PostgreSQL через асинхронный драйвер asyncpg.

| Слой backend | Ответственность |
|---|---|
| `api/routes.py` | Разбор параметров, зависимость текущего пользователя, сериализация, cookie и жизненный цикл сокета |
| `schemas/chat.py` | Входные ограничения, нормализация, разрешённые поля публичных ответов |
| `services/accounts.py` | Регистрация, проверка пароля, срок и отзыв сессии, правило роли |
| `services/dialogs.py` | Проверка участников, создание пары, история и транзакция отправки |
| `repositories/store.py` | Параметризованные запросы, поиск, выборка последних сообщений и пагинация |
| `models/entities.py` | Типы, связи и ограничения четырёх таблиц |
| `core` | Настройки, соединения, криптография, лимиты, единые ошибки и журналы |
| `realtime/hub.py` | Реестр отдельных подключений, проверка сессии перед доставкой и закрытие вкладок при выходе |

## Путь сообщения

1. Форма проверяет длину, блокирует повторную отправку и выполняет POST. При ошибке черновик остаётся в поле.
2. Зависимость FastAPI получает пользователя из серверной сессии. Сервис проверяет принадлежность диалога, блокирует его строку и добавляет сообщение. Идентификатор автора берётся из сессии, время задаёт БД.
3. После commit сервер уведомляет подключённые вкладки обоих участников. Для каждой вкладки повторно проверяется сессия. Один медленный сокет ограничен тайм-аутом отправки.
4. Отправитель получает HTTP-ответ с сохранённой записью. React объединяет события и ответы по идентификатору сообщения. Лента и превью последнего сообщения обновляются независимо.
5. При обрыве клиент переподключается, после первого подтверждённого события перечитывает список и последнюю страницу истории. Более ранние записи доступны по курсору.

WebSocket даёт немедленную доставку при открытом соединении. REST остаётся источником истории, поэтому потерянное уведомление восстанавливается чтением БД. Серверные сессии позволяют немедленно отозвать конкретный вход, включая его открытые вкладки. Хеширование паролей выполняется в пуле потоков.

## Клиент

`main.tsx` восстанавливает сессию и ограничивает маршруты. Навигация по hash поддерживает обновление и кнопки истории браузера. `pages` содержит страницы входа, рабочего пространства, чата и списка пользователей. `features` отвечает за поиск собеседника и подключение WebSocket. `components` содержит общие элементы, `api/client.ts` — типы, обработку ошибок, форматирование времени и объединение сообщений.

На широком экране диалоги и история расположены рядом. На телефоне открыт один экран, из чата можно вернуться стрелкой. При чтении ранних сообщений новые входящие отмечаются кнопкой перехода вниз. Черновики переключаемых диалогов хранятся в памяти текущей страницы.
