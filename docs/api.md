# Контракт API

Базовый путь `/api`. Машиночитаемая схема FastAPI доступна в работающем приложении. [OpenAPI JSON](http://localhost:8080/api/openapi.json)

Браузер отправляет cookie `imsit_session` автоматически. Для каждого POST обязательны разрешённый `Origin` и заголовок `X-Imsit-Request: 1`. Для тела используется JSON. Неизвестные поля во входных объектах отклоняются.

| Метод и путь относительно /api | Доступ, параметры и результат |
|---|---|
| GET /health | Готовность backend и соединения с БД, 200 |
| POST /register | `{"username":"irina","password":"…"}`, новый аккаунт, 201. Для открытия сессии нужен вход. |
| POST /login | Те же поля, 200, публичный аккаунт и Set-Cookie |
| GET /me | Текущая сессия, `{id, username, role}` |
| POST /logout | Текущая сессия, 204, отзыв cookie и соединений |
| GET /users?q=ir | Поиск по началу имени без учёта регистра, исключает себя. До 25 объектов `{id, username}`. |
| GET /dialogs | Диалоги участника, последние активные первыми. `{id, peer, last_message}`, для пустого диалога последнее сообщение равно null. |
| POST /dialogs | `{"peer_id":2}`, возвращает новый или уже существующий диалог, 200 |
| GET /dialogs/{id}/messages | Только участник. `limit` от 1 до 100, по умолчанию 40. `before` исключает указанный id и все более новые. Ответ `{items,has_more}` в порядке возрастания id. |
| POST /dialogs/{id}/messages | Только участник. `{"body":"Привет!"}`, 201, сохранённое сообщение |
| GET /admin/users?after=0 | Только admin. До 50 аккаунтов в порядке id. Для следующей части передайте последний id в after. |

Регистрация принимает 3–32 символа имени после удаления крайних пробелов, разрешены A–Z, a–z, 0–9 и подчёркивание. Сохраняется нижний регистр. Пароль 8–128 символов, одни пробелы запрещены. Регистр пароля значим. Текст сообщения до 4000 символов до обрезки крайних пробелов, переводы строк внутри сохраняются.

## Ошибки

```json
{"error":{"code":"validation","message":"Проверьте введённые данные.","request_id":"<id запроса>","fields":{"password":"Введите пароль длиной 8–128 символов."}}}
```

Поле fields появляется при ошибке параметров. Идентификатор также возвращается в X-Request-ID. Основные статусы — 401 для отсутствующей сессии или ошибки входа, 403 для роли или CSRF, 404 для недоступного диалога, 409 для занятого имени, 422 для валидации, 429 для частоты, 500 для внутренней ошибки. На 429 возвращается Retry-After в секундах.

## WebSocket

Подключение `ws://localhost:8080/api/events` использует cookie и проверенный Origin. При HTTPS клиент выбирает wss. После проверки сессии сервер отправляет heartbeat и повторяет его каждые 20 секунд. После первого события клиент обновляет данные через REST. В heartbeat и в событии `activity.snapshot` поле `activity` содержит состояния собеседников во всех личных диалогах текущего пользователя.

```json
{"type":"activity.snapshot","activity":[{"dialog_id":4,"online":true,"typing":false,"last_seen_at":"2026-11-19T08:15:00+00:00"}]}
```

Статус «В сети» действует, пока подключена хотя бы одна вкладка. Время подтверждённой активности сохраняется в PostgreSQL при heartbeat и при закрытии последнего соединения. Для пользователя без отметки времени значение равно null. При потере связи клиент скрывает устаревшие статусы.

Клиент посылает `{"type":"typing","dialog_id":4,"active":true}` при наборе и `active:false` при остановке. Сервер проверяет сессию и участие в диалоге. Каждый сигнал относится к одной вкладке. Через пять секунд без продления отметка истекает. Набираемый текст остаётся в браузере. Некорректный кадр, чужой диалог или превышение 120 сигналов в минуту на соединение закрывает сокет с кодом 1008.

```json
{
  "type": "message.created",
  "message": {"id":17,"dialog_id":4,"sender_id":2,"body":"Привет!","created_at":"2026-11-19T08:15:00Z"}
}
```

Событие приходит после записи сообщения каждой подключённой вкладке участников. Истечение или отзыв сессии закрывает сокет с кодом 4401. Потеря сети запускает повторные попытки через 0,5, 1, 2, 4, 8 и затем 10 секунд. При возвращении сети возможна немедленная попытка. Подключение и история восстанавливаются через одну точку доступа Nginx.
