# Соответствие итоговой практике

| Раздел задания | Реализация | Проверка |
|---|---|---|
| 1, 12. Парная работа, 1,5 месяца и защита | План на шесть недель, обмен ролями и вопросы для обоих участников | Пройти демонстрацию вдвоём, поменяться частями объяснения, см. team-plan.md |
| 2–4. Регистрация, вход, user/admin | Имена уникальны в PostgreSQL, Argon2id, серверная сессия, локальная команда администратора | Зарегистрироваться, обновить страницу, сравнить доступ к /api/admin/users |
| 3. Допустимый стек | Python/FastAPI, React/TypeScript, Tailwind CSS, PostgreSQL 16 и WebSocket | README, Dockerfile, файлы зависимостей |
| 4. Личные сообщения и история | Каноническая пара, серверное авторство и время, порционная история | Два профиля браузера, диалог в обоих направлениях, перезапуск Compose |
| 5. ERD, нормализация, слои и REST | Четыре таблицы, внешние ключи, API/services/repositories, OpenAPI | docs/erd.md, docs/architecture.md, alembic check |
| 5–6. SPA и асинхронное взаимодействие | Hash-маршруты, fetch, WebSocket, синхронизация после обрыва | Открыть чат в двух окнах и отправить ответ |
| 6. Адаптивность, прокрутка, состояния | Разделённый экран, мобильный возврат, черновик, индикатор новых сообщений, клавиатурная отправка | Playwright, ручная проверка ранней истории и фокуса |
| 7. Безопасность | Сессии, CSRF, CORS и Origin, параметризованные запросы, проверка участника, лимиты | Интеграционные тесты на роль, чужой объект, отзыв и 429 |
| 8. Тесты и документация | Модульные и интеграционные проверки, отдельная PostgreSQL, браузерные сценарии, README | Команды в docs/testing.md |
| 3, 9–10. Docker, CI, локальная работа | Один адрес, тома, проверки готовности, предсобранный SPA, все ресурсы локальные | Запуск без скачивания, перезапуск с проверкой истории |
| 11. Качество реализации | Единый формат ошибок, request id, конкурентное создание пары, несколько вкладок, WebSocket после commit | Сверить ответ ошибки с журналом, запустить расширенные тесты |

Выбор FastAPI и React согласован с пользователем. Серверные сессии, Alembic, перечень полномочий admin и стратегия повторного подключения конкретизируют реализацию. Фактическое распределение работы и готовность участников к защите подтверждает сама пара.
