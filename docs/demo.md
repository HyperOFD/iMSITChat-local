# Сценарий защиты

Подготовьте образы приложения и тестов по README и docs/testing.md. Для демонстрации нужны два независимых профиля браузера и третий профиль для администратора. Две вкладки одного профиля используют одну сессию.

| Шаг | Действие | Наблюдаемый результат |
|---|---|---|
| 1 | Из корня запустите `docker compose up -d --wait --no-build --pull never` и `docker compose ps`. Откройте http://localhost:8080. | Три основных сервиса готовы. Достаточно одного адреса. |
| 2 | В одном профиле зарегистрируйте `irina_demo`, в другом — `maksim_demo`. При повторной демонстрации используйте новые свободные имена или войдите в подготовленные аккаунты. У одного пользователя выполните выход и обычный вход. | Возникают отдельные сессии, обновление страницы сохраняет вход. |
| 3 | У Ирины нажмите **+**, введите начало имени Максима и выберите его. Напишите ему. Откройте появившийся диалог во втором окне и ответьте. | Сообщения видны сразу в обоих окнах. Указаны автор, дата и локальное время. Собственные сообщения выровнены вправо. |
| 4 | Сузьте окно до ширины телефона, выйдите стрелкой к списку и вернитесь в чат. Попробуйте пробельное сообщение и клавиши Shift+Enter и Enter. | Поля остаются доступны, пустой текст отправить нельзя. |
| 5 | Запишите номер диалога из адреса `#/dialogs/ЧИСЛО`. Остановите `docker compose stop`, затем повторите команду запуска из шага 1. | Сессии и история восстановлены. В открытом окне индикатор возвращается в состояние «На связи». |
| 6 | Откройте в профиле обычного пользователя `http://localhost:8080/api/admin/users`. Создайте администратора командой `docker compose exec backend python -m app.admin teacher_demo` и войдите в третьем профиле. Нажмите значок щита. | Обычному участнику возвращается 403. Администратор видит публичные имена и роли. |
| 7 | В профиле администратора откройте `http://localhost:8080/api/dialogs/ЧИСЛО/messages` для диалога из шага 5. Откройте тот же адрес в профиле Ирины. | Третий пользователь получает 404 с request_id, участник — историю 200. Интеграционный тест дополнительно проверяет запрет отправки. |
| 8 | Выполните `docker compose --profile test run --rm tests` после предварительной сборки тестового образа. Откройте ERD и покажите ограничение пары. | pytest проходит на отдельной тестовой БД, рабочая переписка остаётся доступна. |

Для объяснения доставки покажите в инструментах браузера вкладку **Network → WS → Messages**. Сопоставьте идентификатор сообщения в событии с результатом REST. В журнале backend найдите request_id демонстрационного 404. Закончите объяснением, как клиент догоняет историю после разрыва.
