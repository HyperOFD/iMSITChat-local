# iMSITChat

Локальный веб-мессенджер для итоговой практики по МДК.01.01 «Разработка программных модулей». Два пользователя находят друг друга по имени и обмениваются текстовыми сообщениями. Переписка сохраняется в PostgreSQL. Браузер получает новые сообщения по WebSocket.

## Android-клиент

[Установочный APK](artifacts/iMSITChat.apk) использует тот же сервер и аккаунты, что и браузер. Доступны подключение по USB и работа в локальной Wi-Fi-сети. [Установка, выбор сервера и сборка клиента](docs/android.md)

## Запуск

Понадобятся браузер и Docker с Compose v2.24.4 или новее. На Windows подойдёт Docker Desktop с Linux-контейнерами, на macOS — Docker Desktop, на Linux — Docker Engine и плагин Compose. Откройте терминал в каталоге с `compose.yaml`.

```sh
docker compose up --build
```

Откройте [iMSITChat на этом компьютере](http://localhost:8080). Нажмите **Регистрация** под формой входа, задайте имя и пароль. Для второго пользователя откройте приватное окно или другой профиль браузера. В списке диалогов нажмите **+**, найдите вторую учётную запись и отправьте сообщение.

Первичная сборка скачивает базовые образы и зависимости Python и npm. Регистрация в сторонних сервисах не требуется. Время первой сборки зависит от сети и кэша. Для подготовки к защите выполните её заранее на нужной архитектуре процессора. Для запуска в фоне, проверки состояния и остановки:

```sh
docker compose up -d --wait
docker compose ps
docker compose stop
```

После подготовки образов для полностью локального запуска:

```sh
docker compose up -d --wait --no-build --pull never
```

На проверочном стенде macOS arm64 с Docker Desktop, Compose 5.5.1, готовыми образами и существующими томами запуск после удаления контейнеров занял **8,9 секунды** от команды до готовности всех трёх сервисов. Запуск выполнялся с параметрами `--no-build --pull never --wait`. После него проверены вход по прежней cookie и чтение сохранённого сообщения.

Остановка с удалением контейнеров и сети — `docker compose down`. Оба именованных тома сохраняются. В `pgdata` находятся записи, в `credentials` — случайно сгенерированный при первом запуске пароль подключения. Сохраняйте эти тома вместе. У приложения нет предустановленных пользователей.

## Роль администратора

```sh
docker compose exec backend python -m app.admin teacher
```

Введите новый пароль в интерактивном приглашении. Команда создаёт отдельную учётную запись, занятое имя вызывает ошибку. Войдите под ней и нажмите кнопку **Пользователи** со значком щита. Администратор видит имена и роли. Для чтения диалога требуется участие в нём.

## Стек и структура

| Каталог | Назначение |
|---|---|
| `backend/app` | FastAPI, асинхронный SQLAlchemy, asyncpg, Argon2id, HTTP и WebSocket |
| `backend/migrations` | Alembic и начальная схема PostgreSQL 16 |
| `backend/tests` | Правила предметной области и интеграция с PostgreSQL |
| `frontend/src` | React, TypeScript, Vite, Tailwind CSS, локальные шрифты |
| `frontend/e2e` | Браузерные сценарии Playwright |
| `frontend/nginx.conf` | Раздача SPA, проксирование API и WebSocket |
| `deploy`, `compose.yaml` | Локальные сервисы, тома и проверки готовности |
| `.github/workflows/check.yml` | Линтер, тесты, проверка типов, сборка и браузерная проверка |
| `docs` | Архитектура, контракты, защита и демонстрация |

Миграции применяются перед запуском Uvicorn. Проверить версию и согласованность схемы:

```sh
docker compose exec backend alembic current
docker compose exec backend alembic check
```

## Проверки

```sh
docker compose --profile test run --build --rm tests
```

Команда создаёт отдельную тестовую PostgreSQL во внутренней сети. Для повторной проверки без сети подготовьте образ этой командой заранее и опустите `--build`. Браузерная проверка запускается на отдельном стенде. [Инструкции для всех видов тестов](docs/testing.md)

## Настройка и диагностика

По умолчанию открывается только порт 8080 на loopback. Для изменения скопируйте `.env.example` под именем `.env`, задайте `CHAT_PORT` и перечислите соответствующие точные адреса в `ALLOWED_ORIGINS`. Повторите `docker compose up -d --wait`. Для локального HTTP оставьте `COOKIE_SECURE=false`.

| Симптом | Что проверить |
|---|---|
| Порт занят | Выберите свободный порт, например 8090, и замените 8080 на 8090 также в разрешённых origins. |
| Нет подключения к Docker daemon | Запустите Docker Desktop или службу Docker, дождитесь готовности и повторите команду. |
| Первый запуск долго скачивает зависимости | Проверьте доступ Docker к реестру образов, PyPI и npm. Команда повторно использует готовые слои. |
| Ошибка 403 при входе | Сверьте схему, имя хоста и порт адресной строки с `ALLOWED_ORIGINS`. Новый origin требует пересоздания backend. |
| Не приходят уведомления | Индикатор должен показать «На связи». Убедитесь, что backend работает. После переподключения браузер повторно запросит историю. |
| 429 при частых запросах | Дождитесь освобождения минутного окна и повторите действие. |
| Сервис не становится healthy | Посмотрите `docker compose ps -a` и `docker compose logs --tail=40 backend db`. |
